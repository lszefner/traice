Your project must:  - Model a real-world use case as a graph. - Ingest and clean data through ETL/ELT scripts. - Expose meaningful graph queries through a FastAPI service. - Run using Docker Compose. - Include automated tests and clear documentation. - Use Docker, Make and Git as part of the development workflow. - Include at least one **LLM-over-graph or agentic component**.  The goal is not only to produce a functional application. You must also demonstrate that you understand and can justify the main engineering decisions behind your project.  ---  ## Expected repository contents  Your GitHub repository must include:  - `docker-compose.yml` - `app/` - `scripts/` - `tests/` - `Makefile` - `.env.example` - `requirements.txt` - `demo.ipynb` - a comprehensive root `README.md`  The README must contain:  - project description; - installation and execution instructions; - API examples; - screenshots of the working application; - graph schema; - system architecture; - dataset sources; - modeling rationale.  You must also provide a **graph-schema diagram** and explain the modeling alternatives you considered and rejected.  Use a diagramming tool such as draw.io.  ---  ## Team size  Projects must be completed in groups of **up to 5 students**.  A team lead must be identified for each group.  The team lead is responsible for:  - coordinating Git branches; - assigning or reviewing Pull Requests; - ensuring that contributions remain reasonably balanced.  ---  # Agentic / GraphRAG requirement  Every project must include at least one component placing an LLM or an agent on top of the graph.  The expected complexity depends on the project level.  ### Levels 1–2  A **Natural Language → Cypher** system is sufficient.  Example:  > What do I still need to take before I can enroll in Machine Learning?  The system should:  1. receive the natural-language question; 2. generate a Cypher query; 3. validate the generated query; 4. execute it against Neo4j; 5. return a structured response.  Guardrails must prevent unsafe, invalid or inappropriate queries.  ### Levels 3–3+  A genuine **LangGraph agent** is expected.  The agent should be able to:  - reason over several steps; - call tools; - query Neo4j; - optionally call external APIs; - combine multiple sources of information; - expose the sequence of tool calls or graph paths used to produce the answer.  The objective is not simply to call an LLM.  You must explicitly address the fact that LLM-generated information can be unreliable.  Depending on the project, consider:  - query validation; - confidence scores; - schema constraints; - allow-listed Cypher operations; - structured outputs; - fact verification; - distinction between verified facts and AI-generated hypotheses.  ---  # Working with AI coding assistants 🤖  Using tools such as ChatGPT, Claude, GitHub Copilot or similar coding assistants is allowed and encouraged 🥷  However, **a working project alone is not sufficient**.  Modern AI assistants can easily generate:  - FastAPI scaffolding; - Neo4j CRUD endpoints; - Dockerfiles; - simple Cypher queries; - tests; - basic documentation.  *Your evaluation therefore focuses strongly on the engineering decisions behind the implementation.*   ⚠️ You must be able to explain ⚠️  - why you chose a particular graph schema; - why something is represented as a node rather than a property; - why a relationship exists; - why an index is useful; - how a Cypher query works; - how its complexity behaves as the graph grows; - how the LLM component is constrained; - how unreliable AI-generated outputs are detected or handled; - why you selected one graph algorithm over another.  ---  ## Modeling & anti-genericity requirement  Your README or demonstration notebook must contain a short appendix comparing:  1. the graph schema used in your project; 2. a basic graph schema generated by an AI assistant from the same project description.  Explain where your model differs and **why**.  The purpose is not to avoid AI tools.  The purpose is to demonstrate that your team made deliberate modeling decisions rather than accepting the first generated schema without analysis.  ---  # Project list  ### Difficulty levels  | Level | Focus | |---|---| | **1** | Modeling and Cypher foundations | | **2** | Graph engineering, Docker, FastAPI, GDS | | **3** | Advanced graph algorithms, GDS and ML | | **3+** | Agentic systems and GraphRAG |  Datasets have been selected to be real, documented and sufficiently large to support meaningful graph analysis.  ---  # Level 1 — Modeling & Cypher foundations  ## 1. Document the modeling alternatives you rejected.  3. **Create data-import scripts.**     Use the Neo4j Python Driver and efficient bulk-import techniques.  4. **Build the FastAPI endpoints.**     Include CRUD operations where relevant, but focus mainly on meaningful graph queries.  5. **Implement the agentic component early.**     Do not add NL-to-Cypher or LangGraph only at the end of the project.     Guardrails should be designed from the beginning.  6. **Dockerize the application.**     Neo4j, FastAPI and supporting services must run through Docker Compose.  7. **Benchmark and optimize your
